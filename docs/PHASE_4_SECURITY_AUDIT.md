# Phase 4 Security Audit

Project: Migrant Health Support Hub  
Phase: 4 - Aggregated ratings and client-side security

| Security item | Risk | Current control | Evidence files | Verification method | Remaining limitation | Status |
| --- | --- | --- | --- | --- | --- | --- |
| XSS | User text could execute as HTML or script. | Vue text interpolation; no dangerous DOM rendering APIs. | `src/views/*.vue`, `src/components/*.vue` | `rg "v-html|innerHTML|outerHTML|document\\.write|eval\\(|new Function" src` | Manual browser XSS checks still required. | Implemented, pending manual verification |
| Plain-text passwords | Password disclosure in Local Storage. | Ordinary users store `passwordHash` and `passwordSalt`, not plain password. | `src/stores/authStore.js`, `src/utils/password.js` | `rg "password|passwordHash|passwordSalt" src` and manual review. | Front-end hash storage is still inspectable locally. | Implemented, pending manual verification |
| Password hash | Weak or reversible password handling. | PBKDF2, SHA-256, random salt, no reversible encryption. | `src/utils/password.js` | Registration/login logic checks. | Server-side password hashing would be required in production. | Implemented, pending manual verification |
| Session content | Session may expose sensitive data or trusted role. | Session stores only `userId` and `createdAt`; role read from users. | `src/stores/authStore.js`, `src/utils/storage.js` | Inspect `migrantHealthHub.session`. | Local Storage session can be edited by local user. | Implemented, pending manual verification |
| Role manipulation | User may try to become admin through client data. | Registration always creates `user`; route and admin functions check current role. | `src/stores/authStore.js`, `src/router/index.js`, `src/composables/useAppointments.js` | Manual route and admin action checks. | True RBAC requires backend enforcement. | Implemented, pending manual verification |
| Route access | Guests or users may open protected URLs directly. | Vue Router meta guards and Unauthorized page. | `src/router/index.js`, `src/views/UnauthorizedView.vue` | Direct URL checks. | Client route guards can be bypassed locally; backend needed. | Implemented, pending manual verification |
| Appointment ownership | User may delete another user's booking. | Delete function checks `ownerUserId`. | `src/composables/useAppointments.js` | Logic and browser checks with two users. | Local Storage can be edited locally. | Implemented, pending manual verification |
| Rating ownership | User may submit as another user or duplicate ratings. | Rating submit checks current user, active user, resource, score, and updates existing record. | `src/stores/ratingStore.js` | Store logic checks. | Backend required for trusted ownership. | Implemented, pending manual verification |
| Input validation | Invalid data could corrupt state. | Validation for auth, appointments, ratings, status, roles, and storage shapes. | `src/utils/authValidation.js`, `src/utils/validation.js`, `src/stores/ratingStore.js` | Invalid input checks. | Client validation must be repeated server-side in production. | Implemented, pending manual verification |
| Corrupted Local Storage | Bad JSON could white-screen the app. | Storage utilities return safe defaults and stores filter invalid data. | `src/utils/storage.js`, `src/stores/authStore.js`, `src/stores/ratingStore.js` | Manual corrupted JSON checks. | Cannot prevent local tampering without server. | Implemented, pending manual verification |
| API keys/secrets | Secret leakage in repository. | No API integration or secret required; `.env` ignored. | `.gitignore`, source files | `rg "api[_-]?key|secret|token|private[_-]?key" . --glob "!node_modules/**" --glob "!dist/**"` | Demo admin credential is public and documented. | Needs manual review |
| CSP/security headers | Browser policy may be too permissive. | Basic meta CSP added. | `index.html` | `npm run build`; browser check. | Final security headers should be configured by server. | Implemented, pending manual verification |
| Client-side-only limitation | Client controls can be modified locally. | Documentation clearly states limitation. | `docs/SECURITY_REFLECTION_DRAFT.md`, `docs/A2_IMPLEMENTATION_PLAN.md` | Documentation review. | Production needs backend/API. | Documented |
